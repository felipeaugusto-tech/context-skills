## Relevance to This Codebase

The ABCNEW SQL Server database is the single source of truth for all ~240 domain entities, shared by every module with no service-level boundaries. Two independent data access paths (Hibernate via `HibernateManager` and raw JDBC via `DAConnection`) operate against the same database without a shared transaction coordinator. Schema changes require coordinated commits across two Git repositories. There is no automated migration tooling — all changes are manual SQL scripts. Data integrity is the highest operational risk in this codebase after security.

## Data Access Patterns

**Primary path — use for all new code:**
```
BO / Service class
    └──▶ HibernateManager.findByHQL("FROM EntityClass WHERE ...")
    └──▶ HibernateManager.saveOrUpdate(entity)
    └──▶ HibernateManager.delete(entity)
    └──▶ HibernateManager.executeStoredProc(name, params)
```

**Legacy path — do not use for new code:**
```
DAConnection / DatasourceConnection
    └──▶ JNDI DataSource
    └──▶ Raw JDBC PreparedStatement
```

**Transaction pattern:**
```java
// Multi-entity write flows use explicit transactions:
Transaction tx = session.beginTransaction();
// ... multiple saves/updates ...
tx.commit();

// OR Spring declarative:
@Transactional
public void someMultiEntityMethod() { ... }
```

## Schema Migration Process (Current)

1. Write SQL script in `new-platform/deployment-scripts/` (e.g., `ALTER_TABLE_xxx.sql`)
2. Run manually against target environment's SQL Server
3. Track which scripts have been applied — **no automated tracking**
4. Coordinate with `abc-j2ee` repo for HBM changes if entity structure changes

## AI Agent Guidelines for This Area

### Do
- Use `HibernateManager` methods for all data access in new code
- Wrap multi-entity write flows in explicit transaction boundaries (`@Transactional` or `Transaction()`/`commit()`)
- Register any new entity in `new-platform/com.abc.npwar/config/hibernate.cfg.xml` with a `<mapping>` entry
- Place HBM mapping files in the `abc-j2ee` repo under `com/abc/bo/hbm/` — this is the established pattern
- Add new manual SQL scripts to `new-platform/deployment-scripts/` with a descriptive name indicating the change

### Do Not
- Write new code using `DAConnection` or `DatasourceConnection` — these are the legacy JDBC path
- Mix `HibernateManager` and `DAConnection` writes in the same logical operation — no shared transaction
- Call `session.createQuery()` directly — always go through `HibernateManager` helper methods
- Concatenate user input into HQL strings — always use named parameters (`.setParameter("name", value)`)
- Apply schema changes without updating the corresponding HBM file and entity class in `abc-j2ee`

### Always Check
- `new-platform/com.abc.npwar/config/hibernate.cfg.xml` to confirm the entity you're querying is registered
- Whether the HBM file for an entity lives in `abc-j2ee` or locally in `PackageWithSearchType.hbm.xml` before making schema changes
- Whether a write operation touches multiple entities — if yes, ensure a transaction boundary wraps the entire flow
