## Relevance to This Codebase

AccurateBG processes PII (personal background check data) for tens of thousands of individuals across multiple client companies. The security posture has multiple confirmed critical vulnerabilities: known RCE CVEs in deployed libraries, an HQL injection risk in the primary authentication filter, a vendored SAML library with untracked patches, and secrets detected in Git. Security is the highest-urgency SDLC area for this codebase.

## Authentication & Authorization Model

**Authentication method:** SSO/CAS token validation + SAML 2.0 for enterprise IdPs (Ahold/ISAM, Amazon, US Cellular/NetIQ)

**Session management:**
- In-memory Tomcat sessions — sticky sessions on ALB are required
- Session fixation protection via `SessionFixationValve.jar`
- `SecurityFilter` establishes user + company (tenant) context in session on every new request

**Authorization model:**
- RBAC: `Roles` → `RoleFunction` → `Functions` (DB-driven)
- Company-level multi-tenancy via `CompanyConfig` entity
- Admin impersonation ("login-as-user") — embedded in `SecurityFilter.java`; privilege escalation risk

**Account lockout:** Failed attempt counter on `Abcuser` record; threshold-based block enforced in `SecurityFilter`

## AI Agent Guidelines for This Area

### Do
- Treat any modification to `SecurityFilter.java` as requiring a full security review — never make solo changes
- Use parameterized Hibernate queries (`setParameter()`) for all HQL that incorporates user-supplied input
- Verify SAML assertion signatures before any changes to `com/onelogin/saml2/` processing logic
- Check `new-platform/ssl/server.xml` for current TLS configuration when evaluating transport security

### Do Not
- Concatenate user input into HQL or SQL strings — always use named/positional parameters
- Add new endpoints that bypass `SecurityFilter` without explicit security review
- Commit any decrypted secrets, credentials, or private keys to Git
- Modify SAML signature validation or assertion processing code without a security-focused peer review
- Upgrade libraries in `new-platform/common-components/lib/` without a full regression test — API incompatibilities are likely

### Always Check
- Whether a new controller endpoint needs to be added to `SecurityFilter`'s bypass/allow list
- Whether a new data query uses parameterized HQL (not concatenated strings)
- `new-platform/com.abc.npwar/config/{env}/web-np.xml` to confirm filter ordering is intact
