## Relevance to This Codebase

All business logic, external integrations, scheduling, reporting, and authentication live in the backend Java layer. The frontend is server-rendered JSP with no client-side framework. Every feature addition or bug fix is a backend-only change. Understanding the existing BO/DAO/service layering and the Spring XML wiring model is required before writing any code.

## Service Layer Architecture

The application uses a three-layer pattern:

```
Controller (.do endpoints)
    └──▶ Business Object (BO) — domain logic
              └──▶ HibernateManager — generic persistence (primary)
              └──▶ DAConnection — legacy JDBC (do not use for new code)
                        └──▶ SQL Server (ABCNEW)
```

Supporting services running alongside:
- `MailQueueManager` — async email daemon thread (always running in JVM)
- `CacheManager` (EhCache) — application-level caching
- `SessionManager` — HTTP session lifecycle
- State machines in `com.abc.service/src/java/com/abc/sc/statemachines/` — employment verification routing

## AI Agent Guidelines for This Area

### Do
- Register every new controller, BO, and DAO as a Spring XML bean in `JSP-servlet.xml` before using it
- Use `HibernateManager` methods (`findByHQL`, `saveOrUpdate`, `delete`) for all persistence — never use `DAConnection` for new code
- Extend `GenericBO` for new Business Object classes
- Wrap multi-entity write operations in explicit transaction boundaries (`@Transactional` or `Transaction()`/`commit()`)
- Add emails to `MailQueueManager.addToQueue()` — never invoke SMTP directly from a controller or BO
- Mark inactive integration code (CrossMatch, VirtualEdge, etc.) as `@Deprecated` when touching those classes

### Do Not
- Write new code that uses `DAConnection` or `DatasourceConnection` — these are the legacy JDBC path
- Place business logic in Controller classes — delegate to a BO
- Call `SessionFactory.openSession()` directly — always go through `HibernateManager`
- Add `@Component`/`@Service` annotations expecting Spring component scanning — this codebase uses XML-only wiring

### Always Check
- `new-platform/com.abc.npwar/config/JSP-servlet.xml` to verify a bean is declared before wiring it as a dependency
- `new-platform/com.abc.npwar/config/hibernate.cfg.xml` to verify an entity is registered before querying it via HQL
- Whether the flow touches multiple entities — if yes, ensure explicit transaction boundaries exist
